# 走查素材剧本 + 覆盖矩阵（走查步骤 2 产出）

> 素材全部基于 `capabilities.md` 的真实入口生成；覆盖的 C-ID 必须存在于该清单。
> 等级按 SKILL B1：L1 单链直通 / L2 多步往返 / L3 误操作恢复 / L4 状态机长链 /
> L5 并发竞态 / L6 离线重放 / L7 权限矩阵 / L8 边界极限 / L9 故障注入。
> 走查等级：**深度** = 逐层读代码验证；**快速** = grep 确认存在即过。

## 本项目的复杂度画像

| 能力维度 | 是否存在 | 说明 |
|---|---|---|
| 状态机 | ✅ 强 | `pending.json.autoresume` × `state.done` × `resume_decision` 五分支 × `settle_task_action` 两分支 |
| 并发 | ✅ 有 | `on_stop` 与 `job_done` 事件竞态；单实例互斥；关机倒计时与新任务竞态 |
| 离线 | ❌ 无 | 纯本地桌面程序，零网络依赖 → L6 不适用 |
| 多角色权限 | ❌ 无 | 单用户单机 → L7 不适用（用「运行环境差异」变体替代：非 Windows / 无管理员权限 / 无 blender） |
| 硬限制 | ✅ 有 | 单帧尝试次数、无进展轮数、重启次数、磁盘空间 |
| 外部依赖 | ✅ 有 | `blender.exe` 子进程、Windows API（互斥量 / 电源 / 通知 / 自启） |

结论：必须有 **L4（状态机长链）**、**L5（并发）**、**L8（边界）**、**L9（故障注入）** 素材；L6/L7 写理由。

## A. 正常链

**S-01 | L1·单链直通**
操作链：选 `.blend` →（自动读一次配置）→ 帧段填 `1-4` → 点「开始渲染」→ 等渲完
预期：4 帧全部出图；进度条 0→100%；状态栏「渲染完成 · 完成 4/4 · 用时 xs」；日志末尾列出通知三通道结果；`pending.json` 被删除
覆盖：C-10 C-13 C-15 C-30 C-50 C-51 C-60 C-62
等级：深度

**S-02 | L1·多段帧范围**
操作链：点两次「＋ 添加一段」→ 填 `1-4` / `9-10` / `20` → 开始
预期：帧列表 = `[1,2,3,4,9,10,20]`；日志写「3 段，7 帧 —— …」；进度分母 7
覆盖：C-15 C-30
等级：快速

**S-03 | L2·多步往返（场景切换重填）**
操作链：读工程（2 个场景）→ 选场景 B → 观察全表被重填 → 切回场景 A → 再切 B
预期：引擎/采样/分辨率/帧范围/输出模板每次都按该场景重填；场景下拉文案说明「工程有 N 个场景，可切换」
覆盖：C-13 C-14

### 空白格理由

- **离线列整列空**：程序零网络依赖，所有状态都在本地文件（`pending.json` / `.render_state.json`）。无「断网→操作→重放」语义。
- **权限/环境差异列大量空**：单用户单机，无角色差异。仅保留「外部运行环境」变体（blender/工程/输出模板缺失，S-23、S-24、S-15）。
- **表单联动 / 日志区 / 进度栏的并发列空**：这些是纯 UI 同步路径，无共享可变资源；唯一的并发点是渲染线程与 UI 事件队列（已由 S-18 覆盖）。

### 「规则真值表」适用条目（条件 ≥2）

`resume_decision()` 有 4 个条件（存档存在 / 配置可解析 / 前置条件可跑 / 已完成 / autoresume），组合 2^5=32 > 20 → 按 SKILL B3 用 **pairwise** 采样，取 S-12（全 T）、S-13（autoresume=F）、S-14（complete=T）、S-15（可跑=F）、S-25（可解析=F）五条，覆盖所有条件两两组合的关键对。
